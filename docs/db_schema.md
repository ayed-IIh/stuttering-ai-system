# Database Schema Documentation

## Overview

This document describes the PostgreSQL database schema used for storing machine-learning model versions and **multi-label** prediction results for the stuttering detection system.

The schema contains three tables:

* **model_versions** — stores metadata about deployed ML models.
* **predictions** — stores one row per API call with the full per-class sigmoid distribution.
* **prediction_classes** — stores one row per detected class for each prediction (the multi-label child table).

Relationships:

```
model_versions (1) ────── (N) predictions (1) ────── (N) prediction_classes
```

Each prediction is generated by a specific model version and may have **zero or more** detected classes attached (empty predictions are valid — they mean no class crossed the server-side decision threshold).

> ⚠️ **Multi-label note.** Values in `predictions.all_scores` and in `prediction_classes.confidence` are **independent per-class sigmoid probabilities**. They do **NOT** sum to 1.0 across the seven classes — that's a softmax invariant the v2 schema deliberately drops.

---

# Extensions

The schema requires the following PostgreSQL extension:

```
pgcrypto
```

Used to generate UUID values via `gen_random_uuid()`.

# Table: model_versions

Stores metadata for each deployed machine-learning model.

| Column        | Type         | Description                                                                     |
| ------------- | ------------ | ------------------------------------------------------------------------------- |
| id            | UUID (PK)    | Unique identifier for the model version.                                        |
| model_name    | VARCHAR(100) | Name of the machine-learning model (e.g., wav2vec2, HuBERT).                    |
| model_version | VARCHAR(20)  | Version label of the model (e.g., v1, v2, v1.1). Must be unique.                |
| deployed_at   | TIMESTAMPTZ  | Timestamp when the model version was deployed.                                  |
| is_active     | BOOLEAN      | Indicates whether the model is currently active in production.                  |
| artifact_path | TEXT         | Path or location of the stored model artifact (e.g., S3 path, filesystem path). |
| notes         | TEXT         | Optional notes or description related to the model version.                     |

### Primary Key

```
id
```

### Unique Constraint

```
model_version
```

---

# Table: predictions

Stores one row per API call.

| Column             | Type         | Description                                                               |
| ------------------ | ------------ | ------------------------------------------------------------------------- |
| id                 | UUID (PK)    | Unique identifier for each prediction record. Same UUID as the response `request_id`. |
| created_at         | TIMESTAMPTZ  | Timestamp when the prediction was generated.                              |
| audio_filename     | VARCHAR(500) | Name of the processed audio file.                                         |
| audio_duration_sec | FLOAT        | Duration of the audio sample in seconds.                                  |
| all_scores         | JSONB        | Per-class sigmoid probabilities keyed by `shared.labels.CLASS_LABELS`. **Values do NOT sum to 1.0.** Same data as the wire `all_scores` response field. |
| model_version_id   | UUID (FK)    | References the model version used for generating the prediction.          |
| processing_time_ms | INTEGER      | Wall-clock time the model spent processing the audio (ms).                |
| client_ip          | INET         | IP address of the client that made the prediction request.                |
| request_id         | UUID         | Unique identifier for the API request. Mirrors `id`.                      |

### Primary Key

```
id
```

### Foreign Key

```
model_version_id → model_versions.id
```

Each prediction must reference a valid model version. (`ON DELETE RESTRICT`.)

### Unique Constraint

```
request_id
```

Ensures that each API request is stored only once.

### CHECK constraint

```
chk_all_scores_type   :   jsonb_typeof(all_scores) = 'object'
```

The 7-key invariant of `all_scores` is enforced by `PredictionResponse.field_validator` in the application layer — the schema only enforces the value is a JSON object.

---

# Table: prediction_classes

Stores one row per **detected class** for a given prediction (i.e. each class whose sigmoid probability crossed the server-side decision threshold at inference time). Empty predictions have zero rows here.

| Column        | Type         | Description                                                               |
| ------------- | ------------ | ------------------------------------------------------------------------- |
| id            | UUID (PK)    | Unique identifier for this per-class detection row.                       |
| prediction_id | UUID (FK)    | References `predictions.id`. `ON DELETE CASCADE`.                         |
| class_label   | TEXT         | One of the 7 canonical labels from `shared.labels.CLASS_LABELS`.          |
| confidence    | NUMERIC(6,5) | Sigmoid probability for this class. **Independent per row** — values across rows for the same `prediction_id` do NOT sum to 1.0. |
| created_at    | TIMESTAMPTZ  | Insert timestamp.                                                         |

### Constraints

```
chk_prediction_classes_class_label   :   class_label ∈ CLASS_LABELS
chk_prediction_classes_confidence    :   0 ≤ confidence ≤ 1
uq_prediction_classes_prediction_id_class_label   :   UNIQUE (prediction_id, class_label)
```

The uniqueness constraint enforces one row per `(prediction, class)` — the same class can't be inserted twice for the same prediction.

# Indexes

| Index | Table | Columns | Purpose |
|---|---|---|---|
| idx_predictions_created_at | predictions | (created_at) | Time-range queries / sorting. |
| idx_predictions_model_version_id | predictions | (model_version_id) | Joins back to `model_versions`. |
| idx_prediction_classes_prediction_id | prediction_classes | (prediction_id) | Most common access pattern: load all classes for one prediction. |
| idx_prediction_classes_class_label | prediction_classes | (class_label) | Analytics queries like "all predictions where `blocks` was detected." |

> The legacy `idx_predictions_predicted_class` (on the dropped enum column) was removed by migration 002.

# Migration Notes

* `backend/db/schema.sql` is the source of truth for **fresh** databases and produces the multi-label schema directly.
* `backend/db/migrations/001_initial_schema.sql` is preserved as historical record (it created the legacy single-label schema).
* `backend/db/migrations/002_multi_label_predictions.sql` is the forward migration for live databases already running schema 001: it adds `prediction_classes`, drops the `predicted_class` column + index, renames `confidence_scores` → `all_scores`, drops the now-orphan `chk_confidence_scores_keys` CHECK + `jsonb_key_count` helper + `stutterclass` ENUM type. Rollback instructions are in the migration file's header comment.

The schema is **idempotent**: `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, and guarded `ALTER TABLE` blocks make it safe to re-run.

### Transaction Behavior

Migration 002 is wrapped in a single `BEGIN`/`COMMIT`. If any statement fails, PostgreSQL rolls back the entire transaction — no partial schema changes.
